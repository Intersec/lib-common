Attributes and constraints

Attributes annotate declarations and fields. They constrain values, alter the behavior of encoders and decoders, or carry metadata for code generators and applications.

1. Attribute syntax

An attribute is written before the element it annotates — the declaration keyword (struct, enum, …) or the field/RPC it applies to:

@ctype(type = foo__t) @(test:gen1, 2)
struct Foo {
    @min(0) @max(1 << 4)
    int someField;
};

  • Arguments are given either positionally (declaration order) or all named (name=value); the two styles cannot be mixed. Unknown argument names (incorrect argument name), duplicate named arguments, and wrong argument counts (attribute <a> expects <n> arguments, got <m>, or too many arguments) are errors.

  • Argument types are: integer/double (integer arguments accept constant expressions, e.g. @max(10*5) or @min(1 << 5); double arguments also accept integers), strings (double-quoted), and identifiers (in attribute argument lists, identifiers may contain dots and a leading underscore, allowing qualified names).

  • An attribute declared without arguments must be written without parentheses (attribute should not have arguments); conversely, an attribute that requires arguments cannot be written bare (attribute arguments missing) nor as @attr() (attribute <a> expects at least one argument).

  • Repeatable attributes (marked multi below) may be written several times and/or with several comma-separated values: @allow(a, c) ≡ @allow(a) @allow(c). Non-repeatable attributes must be unique (attribute <a> must be unique).

  • An unknown attribute name is an error (incorrect attribute name).

3. Constraint attributes

Constraints restrict the acceptable values of a field. A value violating a constraint is invalid: decoders must reject it (whatever the format), and encoders should refuse to produce it. Default values are checked against constraints at compile time (violation of @min constraint, …).

@min(v) / @max(v)

Inclusive bounds for integer and double fields. The bound must fit the field’s type range (attribute min is lower than minimum value of type <t>, attribute max is larger than maximum value of type ubyte (256 > 255)).

@nonZero

Zero is forbidden (integer and double fields).

@minLength(n) / @maxLength(n) / @length(n)

Inclusive bounds (or exact value) for the byte length of string and bytes fields. @length(n) is equivalent to @minLength(n) @maxLength(n). The argument 0 is forbidden (use `@nonEmpty’s absence to permit empty values).

@nonEmpty

The string/bytes/xml value must not be empty.

@minOccurs(n) / @maxOccurs(n)

Inclusive bounds for the number of elements of a repeated field. The argument 0 is forbidden. On repeated fields, @min/@max/length constraints apply to each element.

@pattern("…")

Character-set restriction for string fields. The supported dialect is deliberately small — one character class applied to the whole string: [<set>]* or [^<set>]*, where <set> contains single characters and a-b ranges, and the characters | . - ^ ? * + { } ( ) [ ] and \ must be backslash-escaped. Any other regular-expression construct must be rejected at compile time (unsupported pattern). Example: @pattern("[a-zA-Z0-9_\-]*").

@allow(m, …) / @disallow(m, …)

For a field of union or enum type, restricts which members (union) or values (enum) are acceptable at this use site: @allow lists the only permitted ones, @disallow forbids the listed ones. The two are mutually exclusive on one field (cannot use both @allow and @disallow on the same field); every name must exist in the target type (unknown field c in MyUnion); a default value must satisfy the restriction (invalid default value on enum field, or invalid default value on strict enum field when the enum is @strict).

@strict (enum declarations)

See Enums.

Example:

struct User {
    @minLength(5) @maxLength(128) @pattern("[a-zA-Z0-9_\-]*")
    string login;

    /* between 5 and 10 elements, each in [-5, 5] */
    @minOccurs(5) @maxOccurs(10)
    @min(-5) @max(5)
    int[] intTab;

    @allow(a, c)
    MyUnion choice;
};

3.1. Combining constraints

Constraint attributes accumulate from three sources: the typedef chain (each typedef adds its attributes), and the use site. When the same bound is given several times, the strictest one wins: the highest @min/@minLength/@minOccurs, the lowest @max/@maxLength/@maxOccurs:

@max(42) @min(5)
typedef uint Digit;

struct Test {
    @max(21) @min(7)
    Digit a;          /* effective range: [7, 21] */

    @max(45) @min(3)
    Digit b;          /* effective range: [5, 42] (typedef is stricter) */
};

Contradictory bounds (@min above @max) are not detected at compile time; they simply make every value invalid.

4. Behavior attributes

@private

On a field (optional, repeated, default-valued, or mandatory void): the field is internal — it must not appear in public interface descriptions (WSDL, OpenAPI…), encoders must be able to omit it when producing data for external consumers, and decoders must be able to reject input that tries to set it. On a class declaration: see Private classes.

@alias(name, …)

On an RPC: declares alternative names under which the RPC is callable. On an enum value: declares alternative names accepted by the text (name-based) formats (Enums).

@noReorder

On a struct: forbids implementations from reordering fields in memory (Structs).

@deprecated

Marks the element as deprecated. Carried through to generated code and interface descriptions; implementations should emit warnings on use.

@nowarn(category)

Suppresses the named compiler warning category for this element. The only defined category is keyword, which lifts the rejection of the names class, new, delete and explicit.

@forceFieldName

Lifts the field naming rules (lowercase first letter, no underscore) for this field, allowing names like my_field.

5. Backend-hint attributes

The following attributes are part of the language (a conforming parser accepts them with the syntax and placement above) but their semantics belong to specific backends, documented in Part II:

@ctype(name)

Alternative type name(s) for the C backend. Each argument must end in t (invalid ctype 'user_t': missing t suffix).

@prefix(Name)

Replaces the enum constant prefix. Note that this has a language-visible effect: it changes the constant names used in constant expressions and default values.

@cdata

Hint for the XML packer (XML representation).

@typescriptNoCollection

Hint for the TypeScript backend.

6. Generic attributes

A generic attribute attaches an arbitrary named value to an element; it has no meaning for the IOP engine itself and is exposed through runtime introspection:

@(<namespace>:<name>, <value>)

  • The name has at least one namespace segment (@(testgen, 1) is an error: generic attribute name (namespaces:id) expected); multiple segments are allowed (@(ns:sub:attr, true)). The character = is forbidden in the name (invalid name for generic attribute: '=' is forbidden).

  • The value is a string, an integer (constant expressions allowed), a double, a boolean, or an inline JSON object written either with braces or as a brace-less key: value list; = is accepted in place of : and trailing commas are tolerated. A value that cannot be parsed is an error (unable to parse value for generic argument '<x>'). With no value at all, @(ns:name) records the empty object {}.

  • Exactly one value is allowed (')' expected, but got ',').

  • A given generic attribute name can appear only once per element (generic attribute 'x:y' must be unique for each IOP object).

  • Generic attributes may be placed on every declaration kind, on fields, and on enum values.

@(test:gen1, 2)
struct MyStruct {
    @(test:gen2, "toto")
    @(test:gen3, min = 1, max = 2)
    int field;
};

6.1. Reserved namespaces

The compat: namespace is reserved for the backward-compatibility checker: @(compat:ignore, true), @(compat:ignoreJson, true) and @(compat:ignoreBin, true) on a struct/union/class, interface or RPC disable the corresponding checks — see Backward compatibility.

7. SNMP attributes

@snmpParam, @snmpParamsFrom and @snmpIndex are specified with the SNMP constructs in SNMP extensions.
