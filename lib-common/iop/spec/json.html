JSON representation

The JSON representation of IOP values has two faces: a canonical output produced by encoders, and a deliberately lenient input grammar accepted by decoders (a superset of RFC 8259 JSON). Identity of fields is by name; the compatibility rules of the JSON family apply.

1. Canonical output

  • Member names are the field names as declared (camelCase), always double-quoted, in declaration order.

  • Pretty layout by default: 4-space indentation, ": " after keys, one field per line, and a trailing newline; encoders also provide a compact mode (no whitespace).

1.1. Value mapping

IOP type JSON output

integers

bare decimal numbers — except that values whose magnitude is ≥ 253 are emitted as quoted decimal strings so that JavaScript readers do not lose precision (encoders may offer an "unsafe integers" mode that always emits bare numbers)

double

%.17g decimal; NaN and ±Infinity are emitted as null

bool

true / false

string, xml

quoted string; printable ASCII except " and \ is emitted raw, everything else (control characters, ", \, non-ASCII) as \uXXXX escapes, with surrogate pairs beyond the BMP. Input text is treated as UTF-8 (invalid bytes as Latin-1)

bytes

Base64 in a quoted string, unwrapped

enums

the value’s name as a string; an undeclared numeric value falls back to the bare integer

void

null (union members and present optional voids); a mandatory void field of a struct is never emitted

structs

nested objects

1.2. Presence

  • Absent optional fields are omitted (never null).

  • Repeated fields are always arrays ([] when empty); single-line format [ v1, v2 ].

  • Default-valued fields are emitted, even when equal to their default.

  • Encoders provide lossless reduction modes — skip fields equal to their default, skip empty arrays, skip empty sub-structs, skip the _class of instances whose dynamic type equals the static type — and lossy ones — skip @private fields, never emit _class, truncate long Base64 values.

1.3. Unions

A union is an object with the single active member, on one line:

{ "wantInt": 42 }

1.4. Classes

A class instance is an object whose first member is "_class", the fully-qualified name of the concrete class; the fields follow from the root ancestor down to the concrete class:

{
    "_class": "test.B1",
    "a": 20,
    "b": "blah"
}

Encoding an abstract concrete class is an error.

2. Lenient input

Decoders accept the following extensions over strict JSON:

  • comments: /* … / (non-nesting), // … and # … to end of line (an unterminated / … */ comment is an error);

  • unquoted member names: identifiers [A-Za-z][A-Za-z0-9_]*;

  • single-quoted strings wherever double-quoted ones are accepted;

  • = as an alias for :, ; as an alias for ,;

  • trailing separators in arrays and objects (separators between members remain mandatory);

  • integer literals in C syntax: decimal, hex 0x…, octal 0…, with the optional unit suffixes (s m h d w, K M G T) — a literal that overflows or falls outside the field’s range, or that carries an unrecognized unit suffix, is an error;

  • arithmetic constant expressions on integers, with the constant-folder operators (-0x7fffffffffffffff + (-1) is valid input); quoted enum names may be operands; a malformed expression is an error;

  • character literals c’x' / c"x" (with the string escape set) as integer values;

  • keyword aliases: yes/no for true/false, nil for null — all accepted for booleans and numeric coercions;

  • doubles with leading dot (.42) and exponents; quoted "inf", "nan" strings coerce into double fields;

  • a repeated field may be given a single value without brackets (one-element array);

  • string escapes: the C set plus \', \/, octal \NNN, \xHH, \uHHHH with surrogate-pair recombination; unknown escapes are kept literally; a raw newline inside a string, or a string that is never closed, is an error.

The top-level value must be an object ({…}).

Decoding errors are reported with line:col: positions; an unexpected token, or an invalid identifier or value, is an error.

2.2. Enums

Enum values are matched by name, ASCII case-insensitively, including @alias names (a name matching no declared value is an error). A quoted integer, a bare integer or an expression is also accepted with only an int32 range check — undeclared values are accepted even for @strict enums; this is an implementation quirk of the reference decoder: do not rely on it, strict enums should be fed declared values only.

2.3. Field matching, unknown and missing fields

  • Member names match the declared field names case-sensitively (the reference implementation offers a USE_C_CASE option matching snake_case input instead). Duplicate members are an error.

  • Unknown members are an error by default; decoders provide an "ignore unknown" mode that skips the value (with full lenient syntax). An input setting a @private field can be rejected ("forbid private" mode).

  • Missing fields: optional → absent; defaulted → default; repeated → empty; mandatory struct/class → recursively default-constructed when possible; mandatory void → fine; any other mandatory field → error.

2.4. Classes

"_class" may appear anywhere in the object (decoders re-scan, so first position is fastest). It must be a string holding the fully-qualified name of the expected class or one of its descendants; unknown names, non-descendants and abstract classes are errors. It may be omitted when the static type is concrete — the instance is then of exactly that type — and is mandatory when the static type is abstract.

2.5. File inclusion

When decoding from a file, a value may be replaced by @include("relative/path"):

  • for string/bytes/xml fields, the raw file content becomes the value (bytes are not Base64-decoded);

  • for struct/union/class fields, the file is parsed as the JSON representation of that type;

  • paths are relative to the including file; includes nest to arbitrary depth with cycle detection. An unreadable file, an @include on a field type that does not support it, or a recursive include is an error.

Encoders can reverse the operation: given a list of (IOP path, file path) pairs, matching sub-values are written to their own files and replaced by @include(…) (one level deep).
