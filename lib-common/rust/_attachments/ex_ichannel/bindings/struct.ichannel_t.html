Fields§

§name: lstr_t

Optional name of the IChannel.

This name is used for exploitation purposes only.

§su: sockunion_t

Resolved address.

Filled with the resolved client or server address. For a client IChannel, this field can be pre-filled if the address resolution is done before; otherwise, the remote_addr field must be filled.

§remote_addr: lstr_t

Client IChannels: non-resolved remote address.

If provided, this address will be resolved and used for each connection attempt; otherwise, the resolution must be done before and provided through the su field. This field is only used for TCP client IChannels.

§impl_: *const qm_ic_cbs_t

Map of the RPC implemented for this IC.

§iop_env: *const iop_env_t

Mandatory IOP environment for the IC.

§on_event: Option<unsafe extern "C" fn(*mut ichannel_t, ic_event_t)>

Mandatory callback to get notified about the connection state (connected, disconnected, no activity, …).

§on_wipe: Option<unsafe extern "C" fn(*mut ichannel_t)>

Optional callback called before wiping the IC.

§owner: *mut *mut ichannel_t

Content set to NULL on deletion

§priv_: *mut c_void

User private data.

§addr_fail_log_level: i32

Log level of the address resolution when it fails. This log level ensures the process can eventually stop if the address resolution cannot be achieved.

§dns_ctx: *mut dns_resolv_ctx_t

Context linked to an address resolution currently in progress.

§peer: *mut c_void

User field to identify the peer.

IChannel unique ID.

Transport layer protocol.

Next slot ID to try for messages slots allocation.

Command value of the current unpacked structure.

§wa_soft: i32

Timeout to be notified when there is no activity.

Timeout to close the connection when there is no activity.

Protocol version of the remote peer.

§cb_level: i16

Account the number of entered callbacks.

§retry_delay: i32

Delay before a reconnection attempt (ms).

§on_creds: Option<unsafe extern "C" fn(*mut ichannel_t, *const ic_creds_t) -> i32>

Callback optionally set by ic_swawn() to retrieve the ic_creds_t of the incoming Unix connection.

§queries: qm_ic_msg_t

Map of queries awaiting for an answer.

List of messages awaiting to be sent, using an IOV.

List of messages awaiting to be sent.

§last_normal_prio_msg: *mut htnode_t

Last message of msg_list having the priority NORMAL.

§local_async_queries: htlist_t§local_async_replies: htlist_t§el_before: *mut ev_t

Handle used to defer some actions.

Can be used to defer actions that cannot be executed synchronously, like scheduling local async queries and replies, or perform the automatic deletion of the IChannel.

§current_fd: i32

Used to store the current file description exchanged on a Unix socket. See ic_get_fd.

§pending: i32

Number of pending queries (for peak warning).

§queue_len: i32

Length of the queue of queries, without accounting canceled queries.

§iov_total_len: i32

Length of the IOV buffer filled for the next write.

§fds: qv_i32_t

Internal stack of file descriptors wrapped in the current message.

§iov: qv_iovec_t

Vector of IOV stacking for the next write.

§rbuf: sb_t

Internal reading buffer.

§ssl: *mut ssl_st

TLS context, if any.

§client_addr: lstr_t

Server IChannels: client IP address.

This field is the IP address of the client connected to the IChannel. This field should not be read directly, ic_get_client_addr should be used instead.

§pending_max: i32

Used in non-release builds to warning about sudden traffic increase that could require investigation.
